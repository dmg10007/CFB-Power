# Weekly predictions vs results report

Launch CFB Power and open Results Report. Choose the season, week, and regular/postseason scope, then click Refresh final scores & generate report. This uses the saved Settings key for one schedule/final-score request, not box-score captures, training, or new forecasts. Select saved reports without another API request. Keep the dashboard running until publication.

Selection is automatic per game: the latest manifest creation timestamp among eligible saved predictions wins. Both creation and as-of timestamps must be strictly before BOTH the saved kickoff and the refreshed kickoff, and home/away team IDs must match. Equal creation times are broken by lexicographically greatest source-run path. Each game is counted once. Saved kickoff strings have minute precision; this is a conservative timestamp check, not an independent proof of when data was originally known. Hashes and local timestamps do not protect against intentional rewriting of manifests and CSVs together. Source training datasets are not revalidated.

The service scans runs/*/predictions_* directories. Missing, incomplete, corrupt, or invalid forecast archives block generation rather than silently selecting older forecasts. A successful report retains the exact source run on each selected row, all scanned source manifest/CSV hashes, original forecast warnings, and the fetched results.json. Selected source warnings are visible in the dashboard. Never edit archive CSVs or their hashes to make a report pass; inspect the identified run first.

Only FBS-vs-FBS games in the requested scope are reported. Unfinished games, unconfirmed kickoffs, and games without an eligible saved forecast remain visible as not scored. No saved pregame prediction means no retrospective prediction is invented. A partial-coverage flag does not necessarily mean games are unfinished; it can also mean missing forecasts. Duplicate IDs, invalid final scores, or a response outside the requested scope block publication.

Summary includes winner accuracy with pick count, score MAE across both team scores, home-margin MAE, total MAE, and Brier with its game count. Lower error/Brier is better. Home margin means home points minus away points, not sportsbook handicap notation. A zero predicted margin is no winner pick but still has a Brier score for a non-tied result. Final ties contribute score/margin/total errors but are excluded from winner accuracy and Brier. Low-history and established-history summaries are separate. No market lines or ATS results are included.

Reports are published to a new data/reports/ID directory with results_report.xlsx (Summary, Games, Not Scored, Provenance), games.csv, summary.csv, not_scored.csv, excluded_predictions.csv, results.json, and manifest.json. Not every excluded candidate means an unscored game: an older eligible version may have been selected. Earlier eligible versions superseded by a newer one are not exclusion errors. Source files and older reports are not overwritten. Output hashes are verified before dashboard display/download. Formula-like text is escaped in CSV/Excel exports.

Refreshing later produces a new report, preserving earlier results if final scores change. Report and forecast actions disable one another within the same browser session while running; there is no cross-session job lock. Do not stop the launcher during active work. Defaults are examples; choose the intended reporting week explicitly.

Validation: 23 scoring/export tests passed offline while building the service; 10 worker/download helper tests passed separately. No live API request or native Streamlit interaction test was run for this feature. Run python -m pytest locally, then generate a report and verify the workbook and coverage counts before merge. Expected suite size is 214 if the previous baseline remains 181. No new dependencies are required beyond the existing project and GUI requirements.
